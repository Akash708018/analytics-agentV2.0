# F7 — v1 parity: the 101 inventory items, assessed

Date: 2026-10-02. Branch: `claude/beautiful-lovelace-07dnwu` (F3–F6 in PR #18, unmerged; F7
stacks on it). API 0.6.0. Owner: Claude Code. Unattended run at the user's request.

## Method

Each `V1-*` item in `docs/steps/F0.md` (the v1 UI at `0ba324b`, read from source in F0) was
compared with the v2 screens on this branch and with API 0.6.0 (`docs/api/openapi.yaml`). Each
gets one verdict:

- **Ported:** the same job, on the named v2 screen.
- **Changed:** the job is done differently, for the stated reason (often a v2 rule: nothing
  preselected, figures exactly as returned, work saved on the server).
- **Dropped:** not in v2, for the stated reason.
- **Blocked:** wanted, but API 0.6.0 has no endpoint. Each is tied to an api-request.

Facts that decide several items:
- `CleaningProposal` has no samples or SQL.
- `ContractProposal` has per-measure `suggested_agg` / `strength` / `reason`, `caveats`,
  `questions` and `provisional`, but no `filled_by` and no evidence list.
- `VersionInfo` has `api_version` and `engine` only, so the server's upload limits are not
  exposed.
- `TurnEvent.type` has no metric-proposal event.
- There are no artifact, report or workspace-reset endpoints.
- `POST /tools/core.*/run` answers 422 `not_a_domain_tool` ("core analyses run through a
  turn").

## Builds in F7

Ports the API already supports:
1. **Download every figure (CSV)** on each result (Tools and the Evidence on Ask). The columns
   are figure, value, unit and source, exactly as the results table shows them. This replaces
   v1's per-result download and the Files page (V1-E08, V1-F04).
2. **Start a new session** on the Session page. v1's "Reset workspace" emptied the workspace
   (V1-S05/S06). In v2, a new session is a fresh workspace and the old one stays at its link, so
   nothing is destroyed and no confirmation is needed. The page says to copy the link first.

Not built:
- A Playwright test suite. D-F2-1 chose one-off browser scripts, and adding a test dependency
  needs the user's yes.
- The blocked items, which are filed as api-requests (below).

## Expected results, stated before running

- Unit: the CSV's first line is `figure,value,unit,source`, and each later line equals the
  results table's row (`null` → `suppressed`, no number formatting). A comma in a figure name
  is quoted.
- AppTests:
  - A tool result shows the download button, and its data is that CSV.
  - The Session page's "Start a new session" makes exactly one `POST /sessions`, moves the tab
    to the new sid, and leaves the old session unchanged on the server.
- Browser (real backend): on Tools, the downloaded file has 1 + N lines for N figures from the
  API, with the same values. After starting a new session, the old link still opens the old
  session.
