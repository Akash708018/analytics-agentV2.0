## What the real backend records (probed before design)

No model keys in this container, so answered turns came from the real app with
`create_app(llm=ScriptedLLM(reply))`, the seam the backend's own tests use: a planner reply
routing to a playbook, an explainer reply wording the figures it is given. On the F4 dataset
(CTR and ROAS approved; ROAS's `conv_value` named for the metric only):

- "Why did ROAS drop in September?" → `plan` {playbook why_roas_dropped, slots period 2026-09 /
  baseline 2026-08, 3 steps} → `tool_call` roas_change_explainer **skipped** (`needs_data`: "no
  column is bound to 'conv_value'") → `figure_check` passed (0 figures) →
  `interpretation_check` passed → `answer`. `answer.results` is empty; `answer.skipped` has 1
  entry; `usage` {llm_calls 2, tool_calls 1, tokens_in_est 363, tokens_out_est 30, per_call,
  model "scripted"}.
- "Where is spend wasted?" → spend_waste **ok** (167 ms), device_geo_split skipped
  (`engine_refused`: "'city' is not a declared dimension"), keyword_ngrams skipped (`needs_data`)
  → `figure_check` "3 of 3 figure(s) match the tool replies." → answer.
  `answer.results` = [spend_waste: 30 figures, 2 series].

## Scope

Ask renders, for each turn:
1. The answer text, then each `flags` entry as "Unresolved check: …".
2. "How this was answered": the plan (playbook, slots, steps; or "no playbook fitted"), every
   tool call (ran with ms, or skipped with its code and reason), the figure check (status,
   detail, corrected), interpretation checks, provider waits, failovers, errors, and a usage
   line (calls; tokens labelled as estimates; model).
3. One "Evidence" expander per `answer.results` entry, rendered by F4's
   `components/results.render_result` (figures as returned, charts as computed).
4. While a turn runs, its plan and tool calls as they arrive. Failed and interrupted turns
   show their events.

## Expected results, stated before running

- Unit: each event type becomes one line holding the backend's values (tool, params,
  code/reason, ms, check status/detail). The usage line says "estimates".
- AppTests (fake turn shaped like the probe): the answer, one skipped step with its reason,
  "Figure check passed", the usage line, an Evidence expander whose figures match the result.
  A running turn shows its plan and first tool call. A failed turn shows its error event.
  Flags appear as "Unresolved check".
- Browser (real app, scripted model): both questions answered. The ROAS answer explains its
  skipped step and has no evidence. The waste answer has one Evidence expander (spend_waste)
  whose figure count equals the API's 30. A refresh keeps both answers.
