# F2 — Sessions, saved work, conflict choices, turn resume

Date: 2026-10-01. Branch: `claude/beautiful-lovelace-07dnwu` (D-F1-6). Base: main `f34dcd2`
(F1 merged, API 0.5.0). Owner: Claude Code (D-F1-5).

## Scope

The backend session becomes the only durable home of the person's work. F0 measured why:
refresh resets `st.session_state`, native navigation drops `?sid=` and page fields, and
Back/Forward restore routes but not fields. F2 builds:

1. **Identity.** The URL holds only `?sid=<uuid>` and the page path. No sid → a landing page
   with one explicit "Start a new session" button (no session is created by just visiting).
   A malformed sid is refused before any request. A sid the backend does not know (404) →
   an "expired or not found" screen with an explicit button; never a silent new session.
2. **Hydration.** On the first run of a browser session, `GET /sessions/{sid}` fills a
   draft from `ui_state` before any widget exists. Widgets are seeded from the draft, and
   their callbacks copy edits back into it. The draft survives the widget cleanup measured
   in F0.
3. **Saving.** `ui_state` is an explicit allowlist: `schema`, `page`, `label`, `dataset_id`,
   `datasets[]` (id, name, rows, columns only). Keys the server already holds that this
   version does not know are passed through unchanged. At the end of each run, if the
   draft's hash differs from the last saved state, one `PUT` goes out with the version last
   read. Nothing else from `st.session_state` is ever sent.
4. **Conflicts.** A 409 `version_conflict` stops saving. A banner offers **Load latest**
   (adopt the server's state; dataset references are unioned, because they point at server
   records) or **Keep my changes** (save mine over theirs at the new version). Nothing is
   adopted or overwritten without that click. 422/413 rejections show the backend's message
   as "Not saved". The local value stays, and no retry happens until something changes.
5. **Navigation.** `st.navigation(position="hidden")` plus sidebar `st.page_link`s that carry
   `query_params={"sid": ...}`. A fresh load of the default route restores the saved page
   once; an explicit route (refresh on `/ask`) wins.
6. **Turns.** Ask lists `GET /sessions/{sid}/turns`. A queued/running turn is polled by id
   (`st.fragment(run_every=…)`). A refresh resumes polling, and never sends the question
   again. A `POST /turns` that times out is checked against the turn list. If it was not
   received, the person decides with an explicit "Send again". Question drafts stay in the
   browser (free text, possible PII) and are never put in `ui_state`.
7. **Minimal upload (Data page)**, because a turn needs a dataset and the API has no
   dataset listing: upload, a card from `GET /datasets/{id}`, the backend's refusals and
   layout questions shown as returned. Answering layout questions, cleaning, domain, contract
   and the evidence view of answers are later milestones.

Not in F2: rendering ToolResults/figures/charts, keyword groups, guided approvals, v1 parity.

## Expected results, stated before running

- Unit/AppTests (new): no sid → landing, zero backend writes until the click. Malformed sid
  → zero requests. Unknown sid → expired screen. Unreachable service → service message, no
  page. Hydrated label/dataset/page appear in a fresh AppTest with the same sid. One edit →
  exactly one PUT carrying the version read; a rerun with no edit → no PUT. External version
  bump + edit → 409 → banner, and no further PUT until a choice. Load latest shows the
  server's value; Keep mine PUTs mine at the server's version. An email in the label → "Not
  saved" with `ui_state_rejected`, no retry loop. Sidebar links carry the sid. Submitting a
  question → exactly one POST. A fresh AppTest during a running turn → zero POSTs, a running
  status, then the answer once the fake finishes. A timed-out POST → no automatic resubmit.
  Upload → `datasets[]` holds metadata only.
- Existing F0/F1 tests: still pass. F0's landing test changes because the landing now has
  one explicit button. The F0 probe tests are unchanged.
- Browser (one-off Playwright script against the real backend, D-F2-1): a label typed then
  refreshed comes back. Sidebar navigation keeps `?sid=`. Back/Forward keep it. Refresh on a
  non-default route stays there with fields restored. A second tab's stale save shows the
  conflict banner. A refresh during a running turn shows it running and then done, with the
  backend holding exactly one turn.

Failures on the way, each fixed in code (no test was weakened):

- AppTest's `switch_page` ran `pages/session.py` **without the router**. Streamlit's legacy
  `pages/` directory registers each file as a standalone page, and AppTest matched that hash
  first. So no save happened (`IndexError` on the missing PUT). Renamed `pages/` → `views/`
  (D-F2-2).
- Three Ask tests: AppTest does not follow a page switch made by the app (`st.switch_page`),
  so the next `run()` went back to the default route. A browser does follow it (steps 11–14
  below). Those tests now open `/ask` explicitly, which is what a refresh on `/ask` does.
- Self-review before commit: "Start a new session" cleared the session cache but kept
  browser-only keys, so an unsent question could be shown (and re-sendable) in the new
  session. It now clears `ui.*`, `ask.*`, `data.*` too. The test failed with the old clearing
  and passes with the new one.
- Self-review before the browser check: navigation alone saved `page`, so two tabs that only
  navigated would have shown conflict banners with no work at stake. Now a 409 whose only
  difference is `page` adopts the server's version and keeps this tab's page (D-F2-3; unit +
  AppTest).

### Browser finding: a save cut in half by Streamlit (C7)

A second script typed into the label **without Enter**, then clicked the sidebar's Data link.

Before the fix:

```text
B0   after one click: url / · h1 "Analytics agent" · backend v2 label ""
B1   no Enter, clicked Data → backend v2 label "" page "data"
```

The screenshot showed the conflict banner against **the same tab**: "This tab: typed, no
Enter / session" vs "Saved elsewhere: (none) / data". Temporary logging in `app.py` (removed):

```text
DBG 2027.023 run page=data v=1 label=''
DBG 2027.031 pre-save page=data v=1
DBG 2027.038 run page=session v=1 label='typed, no Enter'
DBG 2027.041 pre-save page=session v=1
DBG 2027.083 saved page=session -> conflict v=1
```

The click produced two reruns: the navigation (`page=data`) and the field's blur commit
(`page=session`). The data run's PUT reached the server (v2), but that run never logged
"saved". Streamlit stopped it for the newer rerun at its next session-state access: in
`SafeSessionState`, every read and write calls `_yield_callback`. That access was the line
recording v2. The session run then saved with v1 and got a 409 from its own write.

Fix: after a network call returns, `maybe_save` and the upload callback update only the
dicts they already hold, never `st.session_state`. `seed()` keeps a widget value whose
`on_change` was cut short instead of silently dropping it. Regression test
`test_a_save_stopped_after_its_put_still_records_the_new_version` stops the run at the first
session-state access after the PUT. Falsified by putting back one session-state write after
the PUT:

```text
--- falsified (expect FAIL):
FAILED frontend/tests/test_f2_state.py::test_a_save_stopped_after_its_put_still_records_the_new_version
1 failed, 25 deselected in 0.05s
--- restored (expect pass):
1 passed, 25 deselected in 0.02s
```

(My first attempt at this falsification used `git stash`, which silently stashed nothing
because the files were untracked, so it "passed" against the fix. It was redone as above.)

After the fix, servers restarted with a fresh state directory:

```text
B0   after one click: url / · h1 "Analytics agent" · backend v2 label "typed, no Enter" · conflict banner: 0
B1   no Enter, clicked Data → backend v3 label "typed, no Enter" page "data"
B2   reload, back to Session → label "typed, no Enter"
B3   typed, reloaded at once (no Enter/blur) → label "typed, no Enter"
```

Limits observed, not defects of F2:

- B0: the first click after typing commits the field. The blur's rerun comes last, so the tab
  stays on Session, and a second click navigates. Nothing typed is lost or misreported.
- B3: text typed and then refreshed at once (no Enter, no blur) never reaches Streamlit, so
  it is not saved. F0 flagged this; the field's help can say "press Enter to save" if
  wanted.

Servers stopped (`pgrep` prints nothing for `streamlit run|uvicorn --factory`). The last
change, clearing browser-only keys on "Start a new session", came after these browser runs.
Its AppTest covers it; the browser steps start from a fresh landing, where there is nothing
to clear.

## Appendix: browser-check harness (scratchpad, not in the repo)

`slow_backend.py`, served with `uv run uvicorn --factory slow_backend:make --app-dir <dir>`:

```python
import os
import time

from backend.api.app import create_app


def slow(turn, emit):
    emit("plan", {"playbook": None, "steps": ["synthetic.wait"]})
    time.sleep(float(os.environ.get("SLOW_SECONDS", "8")))
    return {"text": f"Synthetic answer to: {turn['question']}", "flags": [], "playbook": None,
            "results": [], "skipped": [], "usage": {"llm_calls": 0, "tool_calls": 0}}


def make():
    return create_app(runner=slow)
```

`browser_check.cjs` (steps 1–21) and `blur_check.cjs` (B0–B3) use only
`page.goto/reload/goBack/goForward`, `getByRole/getByLabel/getByText`, `fill/press/click`,
`setInputFiles`, and `fetch` against the backend for turn and session counts. Labels are
matched exactly (`{ exact: true }`), because the help icon's aria-label repeats the field label.
