## Implementation

- `APIClient` reads `ANALYTICS_API_URL`, supports a base path, validates the URL,
  and URL-encodes resource IDs. Context manager/close release connections.
- Explicit HTTPX timeouts: connect/pool 5 seconds; read/write 30 seconds. These
  limit inactivity, not total elapsed request time. No retries, redirects, or
  environment-proxy forwarding. No request bodies or response content logged.
- One `APIError` boundary handles config, transport, HTTP, and invalid-success
  JSON errors. Status/code/message/payload remain accessible; 409 raises the
  subclass `VersionConflict` carrying `current`. Invalid conflict data still
  raises that subclass with current=None, without an implicit retry.
- All 29 operations have named methods, including multipart upload and the
  future stub routes. Figures, chart points, approvals, and fork choices pass
  through unchanged. The client does not validate analytics, compute figures,
  persist state, or silently choose an answer.
- Prism reads `docs/api/openapi.yaml` unchanged. The Node tool is pinned and
  locked under frontend; only Prism is a direct Node dependency. Python direct
  dependencies are unchanged. Test tooling uses the YAML parser already bundled
  with Prism to obtain examples directly from the source of truth.
- All-contract tests compare operation coverage, request method/path/body,
  response status, and entire response examples. Error selection uses a test-only
  transport that adds Prism's Prefer header. Production client has no mock mode.
- The product landing and F0 state probe are unchanged. Session hydration,
  UI-state saving, conflict buttons, and turn resume remain F2 work.

## API request and limitations

[Issue #4](https://github.com/Akash708018/analytics-agentV2.0/issues/4), labelled
`api-request`, initially requested required path-parameter declarations on 17 stub operations
and status-specific error examples. Prism can route these endpoints, so this is
not a current F1 blocker. It does advertise empty placeholder segments in its
startup route examples. Forced-error evidence:

```sh
frontend/.venv/bin/python - <<'PY'
import httpx
response = httpx.get('http://127.0.0.1:4010/datasets/ds_ads_2026q3/profile', headers={'Prefer': 'code=501'}, timeout=5, trust_env=False)
print('GET /datasets/ds_ads_2026q3/profile (Prefer: code=501)')
print(response.status_code, response.text)
PY
```

```text
GET /datasets/ds_ads_2026q3/profile (Prefer: code=501)

```

The client raises for the HTTP status and preserves the misleading example; it
does not rewrite it. Unit cases separately check a realistic not_implemented
error/milestone. Prism is stateless: success examples do not demonstrate saved
sessions, real uploads, or turn execution/resumption.

Correction after the concurrent 0.3.0 merge: 15 of those 17 parameter declarations
are now present. Only keyword-group GET and actions POST still lack dataset_id
declarations. Generic ErrorBody examples are still shared across error statuses.
The profile 501 output above is historical 0.1.0 evidence; profile is no longer
declared as a 501 endpoint in 0.3.0. Issue #4 remains applicable to the two routes
and status-specific examples.
