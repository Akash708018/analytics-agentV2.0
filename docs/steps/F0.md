## Session design grounded in F0 (implementation belongs to F2)

1. Durable authority is the backend session, identified by a random UUID `sid`.
   URL-only identity cannot restore values without `GET /sessions/{sid}`.
2. Store page identity in backend `ui_state`. Route paths can also express the
   page: both A/B history and B reload worked. Validate page IDs against an
   allowlist and hydrate before rendering any widget. An explicit history route
   selects the displayed page; missing page identity falls back to the saved page.
3. Do not ship the measured native navigation unchanged: it drops `sid`. F2
   navigation must carry `sid` on every destination and preserve real browser
   history, then repeat this browser test. No field values belong in URLs.
4. Stable `ui.*` widget keys alone do not prevent widget cleanup. Keep the
   durable draft in server state and rehydrate values before each page's widgets
   are instantiated. Keep request/version/bookkeeping distinct from serializable
   widget values; serialize only an explicit safe allowlist, never all session_state.
5. Widget callbacks mark changes; an end-of-rerun hash check issues at most one
   versioned save. Version conflicts require explicit Load latest / Keep my
   changes. Do not silently discard, overwrite, or claim an unsaved draft is saved.
6. Keep dataset IDs and display metadata, not data rows, in UI state. Uploaded
   data remains server-owned; render a dataset card after hydration. Restore
   contract and keyword edits from server records, not only the upload widget.
7. Chat and in-progress answers are server-owned. Save a returned `turn_id`
   immediately; reconnect by polling it and fetching history. A fresh browser
   session must not trigger a second POST for an already submitted question.
8. Persisted answers and edits must exclude PII and secrets from `ui_state`;
   use the backend's dedicated records where sensitive/free text is involved.
   Raw text not yet submitted by Streamlit (before Enter/blur) is outside this
   measurement; F2/F7 must distinguish saved draft from browser-only keystrokes.

This follows the requested backend-owned session direction. It does not change
the API contract, introduce storage, or claim that F2 requirements are complete.

### Dynamic analysis fields exposed by the real backend

These are source-derived possibilities, not calls run against a dataset.
The real backend takes the registered function's parameters after `con`, `gate`,
and `scope`, omitting `**params`. Function defaults determine requiredness, but
most optional **UI** values are deliberately blank; they must not be confused
with engine execution defaults. Source:
`src/analytics_agent/webapp/real_backend.py:692–760`.

Field choices and defaults:

- `measure`: confirmed contract measure names, first selected. `against`: other
  aggregatable measures rotated ahead of the first measure, followed by
  per-row-only measures. `dimension`/`rows`: contract dimensions sorted by
  distinct count; `entity`: reverse of that order; `column`: dimensions then
  measures; `columns`/`second_dimension`: dimensions with first rotated to last.
  Required column selectors use first option; optional selectors start blank
  except `measure`. With no options, the UI falls back to text.
- `grain`: `day`, `week`, `month`, `quarter`, `year`, initially `month`.
  `method`: `auto`, `parametric`, `rank`, initially blank.
  `cohort_retention.period`: `week`, `month`, `quarter`, but optional-default
  clearing means the UI initially selects nothing despite the intermediate
  backend assignment of `month`.
- Number fields: `n`, `limit`, `bins`, `threshold`, `confidence`, `alpha`, `power`.
  Other parameters are text, including `event`. Date-like text fields show
  YYYY-MM-DD help. Period/baseline help describes YYYY-MM, YYYY-Qn, or YYYY.
- Required period/baseline defaults, when available, use the last two months
  within the contract window; before/after defaults split the contract window
  in two. These are v1 backend computations, not logic to copy into v2 frontend.

### Persistence implications inferred from this version

- **V1-P01 — Workspace identity already has URL recovery.**
  `workspace_id()` reads `ws` only when absent in session state, accepts only
  `ws_` plus 12 lowercase hex digits, otherwise creates an id, then writes the
  chosen id back to the query string. This final v1 commit contains a partial
  refresh fix; it is inaccurate to claim its code relies only on session state
  for workspace identity. Source: `ui/components.py:19–38`.
- **V1-P02 — UI working state has no server hydrate/save layer.** Ingest draft,
  file token/path, upload choices, cleaning proposals/checks, contract draft and
  widget keys, Explore fields/results, chat, motion, and animation nonce are
  held in Streamlit session/widget state. Screens call backend to load domain
  data but do not restore a generic saved UI-state document. Source: the
  individual screen items above; `ui/backend.py:19–28`.
- **V1-P03 — Backend existence differs from filled fields.** The backend object
  is process-cached and indexed by workspace id; fake mode is the default and
  uses memory; real mode imports the engine directly. A retained `ws` may allow
  datasets/artifacts to be found through the backend while unsubmitted form
  edits and client chat are gone. This is a source-based possibility, not a
  measured refresh guarantee or a claim about server restarts/expiry.
  Source: `ui/backend.py:1–8,19–28`; `ui/components.py:24–38,74`;
  `ui/screens/files.py:18–19`.
- **V1-P04 — No turn resumption protocol.** The chat call runs inline and the
  assistant entry is appended only after it returns. No persisted turn id,
  polling endpoint, or reload recovery path appears in the screen.
  Source: `ui/screens/chat.py:89–103,120–130`.
- **V1-P05 — Navigation does not serialize fields.** The app declares the seven
  Streamlit pages, but no v1 page-state document or explicit saved history is
  present in these screens. Workspace-id query recovery does not serialize
  current page fields. Back/Forward and query preservation need live Streamlit
  measurements; they are not established by reading this code.
  Source: `ui/app.py:30–43`; `ui/components.py:24–38`.

### Gaps relevant to v2, without changing F0 scope

The enumerated v1 app has no domain confirmation/start screen, marketing tools
panel, keyword-group editor, two-tab version-conflict controls, session-expired
screen, or durable turn-resume UI. Those are v2 milestone requirements, not
missing inventory entries. Current v1 also has server-driven defaults/preselected
cleaning checks and frontend number formatting; record those as behaviors to
assess against v2's explicit-choice and exact-figure requirements, not patterns
to copy. No engine-importing v1 code was copied into the v2 scaffold.
